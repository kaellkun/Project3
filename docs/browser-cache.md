# スマホ・ブラウザーの更新とキャッシュ

## 動作

- ページを新規に読み込む／再読み込みするたびに、起動単位の `v` をURLに付けます。
- 対象: ゲームCSS、起動JS、コアJS、プラグイン、WASM、データベース・マップJSON、画像、音声、フォント、動画、エフェクトとその参照素材。
- エンジン標準ローダーを通らないプラグイン独自の読み込み（LN_FilmicFilter の `data/filters/*.json`、LicenseNotice の `README.md`）も `Utils.cacheBustedUrl` を経由します。
  独自に XMLHttpRequest / fetch / `.src` でファイルを読むプラグインを追加した場合は同様に包んでください。
- 同一起動中は同じURLを使い、メモリー上の素材キャッシュは維持します。暗号化素材にも対応します。
- 通信量は増えます。オフライン動作を保証する方式ではありません。
- localStorage / IndexedDB のセーブデータや設定は削除しません。

## スマホ実機で更新されないとき

1. プレイ中なら先にセーブしてください。
2. ゲーム配下の [キャッシュ再読み込みページ](../clear-cache.html) を開いてください。
   このページ自身が古い場合は、URLの末尾に `?refresh=20260915` など毎回異なる値を付けて開きます。
3. 通常はゲームへ自動的に移動します。キャッシュAPIが拒否された場合は警告と再読み込みボタンを表示します。
4. 更新した内容とセーブデータが残っていることを確認してください。

スマホで既存タブやホーム画面アプリに戻っただけでは、ページの起動処理は再実行されない場合があります。
「戻る」によるBFCache復元も同様です。プレイ中の未保存状態を失わないよう、自動強制リロードはしません。
更新確認には明示的な再読み込みか上記ページを使用してください。

## 配信側の注意

`caches.delete()` などの Cache Storage API は、通常のHTTPキャッシュを削除しません。
再読み込みページではゲーム配下の Cache Storage エントリーと Service Worker 登録を対象に処理し、
HTMLと各素材のURLを更新してHTTPキャッシュを回避します。同一ホストの別パスのキャッシュは削除しません。
このゲーム自身は Service Worker を登録していません。

**HTMLそのものの古いキャッシュやCDNの配信設定は、ゲーム内JSだけでは完全に解決できません。**
公開先では以下を確認してください。

- `index.html` / `clear-cache.html` のHTTPレスポンスに `Cache-Control: no-cache` または `no-store` を設定する。
- CDNが `v` と `cache-cleared` のクエリを無視していないことを確認する。必要ならCDNの古いキャッシュを無効化する。
- 親サイトの Service Worker が古い応答を返す場合、その管理側で更新する（親サイトの登録は勝手に解除しません）。
- 更新したHTML・JS・データ・素材を公開先へ一緒にアップロードする。

ブラウザーの開発者ツールでは、キャッシュ無効化を**オフ**にした状態で2回読み込み、
`data/System.json` / マップ / 画像などの要求URLに付く `v` が起動ごとに変わるか確認できます。
ネットワーク一覧を `-v=` などで絞り込み、`index.html` と `icon/icon.png` 以外に `v` のない要求が残っていないことも確認してください。
（2026-09-16 時点、タイトル→マップ→戦闘まで進めた実ブラウザ確認で、この2件以外はすべて `v` 付きです。）
ローカルファイル表示だけではHTTPキャッシュの検証にならないため、HTTP(S)配信で確認してください。

## 回帰テスト

`node --test tests/cache-policy.test.cjs` でURL生成、各ローダー、暗号化素材、
API未対応・拒否時の処理、ゲーム単位のクリア範囲を検証します。
