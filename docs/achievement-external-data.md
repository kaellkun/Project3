# 実績をテキストファイルで編集する

## 導入済みの構成

- 拡張: [AchievementExternalData.js](../js/plugins/AchievementExternalData.js)
- **編集するファイル: [Achievements.json](../data/Achievements.json)**
- [プラグイン登録](../js/plugins.js)で、本体 → カテゴリアドオン → 本拡張の順に有効化済みです。

元の実績プラグインは改変していません。本体の実績リストとカテゴリ設定アドオンのカテゴリリストを外部データで置き換えます。ポップアップ、メニュー表示、保存先などは引き続き既存のプラグイン設定を使います。カテゴリ設定アドオンは省略しても動作します。

ツクールのエディターを開いたまま導入した場合、エディター側の古い設定で上書きされないよう、プロジェクトを開き直してプラグイン管理で登録状態を確認してください。

## 編集の手順

1. [Achievements.json](../data/Achievements.json)をVS Codeなどで開きます。
2. `achievements` 内のサンプルをコピーし、`key` と `title` などを書き換えます。
3. UTF-8で保存し、ゲームを再起動します。起動中の即時再読込は行いません。
4. タイトルまたはゲーム内メニューの「実績」で確認できます。

実績はファイル内の順番で並び、カテゴリは `category` が最初に登場した順になります。同じカテゴリ名は自動でまとめられるため、プラグイン管理でカテゴリを追加する必要はありません。

JSONでは項目間をカンマで区切り、最後の項目にはカンマを付けません。文字列は半角のダブルクォートで囲みます。`//` や `/* */` のコメントは使えません。編集用メモは `$comment` に書いてください。

## 項目一覧

| 項目 | 必須 | 内容・省略時の値 |
| --- | --- | --- |
| `key` | 必須 | 重複しない管理ID（文字列）。前後の空白は除去されます |
| `title` | 必須 | 実績名 |
| `description` | 任意 | 獲得後の説明文。省略時は空欄 |
| `hint` | 任意 | 未獲得時のヒント。空欄なら本体が説明文を表示 |
| `icon` | 任意 | アイコン番号。0以上の整数、初期値 `0` |
| `category` | 任意 | カテゴリ名。省略時はメモ欄のカテゴリタグ、なければ「その他」 |
| `isSecret` | 任意 | `true` で未獲得時に非表示。初期値 `false` |
| `revealSwitchId` | 任意 | ONで秘密実績を一覧に表示するスイッチ。初期値 `0`（無効） |
| `revealVariableId` | 任意 | 秘密実績の表示判定に使う変数。初期値 `0`（無効） |
| `revealThreshold` | 任意 | 変数がこの値を **超えたら** 表示。初期値 `0` |
| `note` | 任意 | 本体・アドオン用のメモタグ。初期値は空欄 |
| `$comment` | 任意 | 編集用メモ。ゲームの表示・判定には使いません |

`description`・`hint`・`note` は普通の文字列のほか、サンプル1件目のような文字列配列にすると1要素が1行になります。文字列内で改行する場合は `\n`、ツクールの制御文字のバックスラッシュはJSON上で `\\` と書きます。例: `"\\c[2]説明\\c[0]"`。

数字は `82` のように引用符なしで指定します。真偽値も `true` / `false` と書き、`"true"` にはしません。

`category` を明示した場合は、メモ欄のカテゴリタグより優先します。カテゴリ名には `<`・`>`・改行を使えません。本拡張はカテゴリを自動生成するため、カテゴリ設定アドオンのID接頭辞による割当は使いません。

### 秘密実績について

導入済み本体の独自拡張に対応しています。スイッチON **または** 指定変数が閾値より大きいとき、未獲得でも一覧に表示されます。閾値が `10` なら変数が `11` 以上で表示されます。

これは**表示の解禁だけ**で、実績の獲得ではありません。獲得には下記のコマンドが必要です。タイトルから開いた際の変数・スイッチ参照などの挙動も本体のままです。

## 実績を獲得させる

イベントコマンド「プラグインコマンド」で、実績プラグイン本体の「実績の獲得」を選び、管理IDに対象の `key` を指定します。

| サンプルの管理ID | 表示名 | カテゴリ | 配置例 |
| --- | --- | --- | --- |
| `story_first_step` | 冒険の始まり | 物語 | 旅立ちイベントの最後 |
| `story_first_request` | はじめての依頼 | 物語 | 依頼完了イベント |
| `battle_first_win` | 初勝利 | 戦闘 | イベント戦闘の勝利分岐 |
| `explore_first_treasure` | 小さな宝探し | 探索 | 宝箱イベント |
| `explore_hidden_place` | 隠された場所 | 探索 | 秘密の場所の発見イベント |

サンプルは**データ定義のみ**です。歩数・戦闘勝利・宝箱などを自動監視する機能はありません。既存マップやイベント、スイッチ、変数には変更を加えていません。5件目は秘密実績のため、初期状態では一覧に表示されません。

## 保存・公開時の注意

- 獲得状況は本体の独立した保存先で管理され、通常のセーブスロットをまたいで共有されます。本拡張は保存内容を消去しません。
- **公開後は `key` を変えないでください。** 同じIDなら実績名や並び順を変えても獲得状態を引き継ぎます。IDを変更すると別実績になります。
- 外部定義から削除したIDは、本体の獲得状況読込時に除外されます。その後の実績保存で履歴からも失われるため、獲得履歴を残したいIDは削除しないでください。
- データファイルは `data/` 以下に置きます。変更する場合だけ本拡張の「実績データファイル」を設定します。
- 戦闘テスト・イベントテストも同じ外部データを使います。テスト中の獲得は本体と同じ保存先に記録されます。
- デプロイ・アップロード後も [Achievements.json](../data/Achievements.json) が含まれていることを確認してください。未使用ファイル除外を使う場合も必要です。
- ファイルが見つからない場合は通常のロードエラーになります。修正後に「Retry」が利用できます。
- JSON書式不正・ID重複・必須項目不足・型の誤りは、対象ファイルと理由を表示して起動を止めます。JSON構文エラーの位置表示は実行環境によります。修正後は再起動してください。
- [既存のキャッシュ対策](browser-cache.md)を利用して読み込むため、HTTP配信・NW.jsテストプレイの両方で同じ経路を使用します。
