# Project3 新UIプラグイン案 — JRPG Adaptive UI

作成日: 2026-09-15 / 状態: 設計提案・未実装

## 1. 結論

**「PCのUIを縦画面へ縮小する」のではなく、共通の操作モデルに、PC用とスマホ用の異なる配置を用意する。**

仮称 `JRPG Adaptive UI`。ゲーム内では一つのUI製品として扱い、開発時は責務ごとに分割する。まず道具画面で読みやすさと操作性を検証し、合格後にメニュー・装備・戦闘へ広げる。既存UIへさらに補正プラグインを重ねる方式は採用しない。

- **PC:** 一覧・説明・仲間を並べ、少ない移動で比較できる。キーボード／ゲームパッドの連続操作を維持。
- **縦型スマホ:** 一列の一覧と必要なときだけ開く下部パネル。文字と押せる面積を確保し、片手操作を妨げない。
- **共通:** アイコン＋日本語ラベル、常に分かる戻り先、操作対象・使用者・対象者の区別、HP/MP/TP・状態異常・装備差分の優先表示。
- **開発:** 座標計算、入力、画面遷移、ゲーム処理を分離。画面を追加しても別の画面の配置やキー設定を壊さない。

比較用の独立した [UI見本](docs/ui/ui-preview.html) を同梱する。道具画面のPC／縦型スマホ配置と、選択→対象選択→使用の流れを試せる。ダミーデータを用いたHTMLであり、MZプラグイン、戦闘実装、実機性能の証明ではない。ゲーム・セーブデータには接続しない。

## 2. 現状の根拠と課題

有効構成の一次情報は [プラグイン登録](js/plugins.js)。[README](README.md) の有効プラグイン一覧は現状を網羅していないため、登録と実装を優先した。

| 確認した実装 | 設計上の課題／新案での対応 |
| --- | --- |
| [縦画面拡張](js/plugins/VerticalDisplayFullscreen.js) は描画領域を縦へ伸ばす一方、`Graphics.boxWidth/boxHeight` を元のUIサイズに固定 | UIの物理的な読みやすさは改善しない。ゲーム世界の見せ方とUI領域を別に設計する |
| [配置変更](js/plugins/FlexibleTopDownUI.js) は `Graphics` のサイズで縦横を判定し、複数シーンの矩形・列数を直接変更 | CSS表示幅・入力機器の判定が他のプラグインと不統一。判定元を一本化する |
| 同プラグインの多くの再配置は `create()` 時に実行し、`move()` のみでサイズ変更 | 回転後の再配置、内容ビットマップ、行数、カーソル、ゲージの更新までを一つの処理にする |
| 戦闘のスキル一覧の高さ計算にヘルプ領域の確保がなく、両方が同じ領域を使いうる | 可視状態を含めて排他的な領域を割り当てる。重なりは実機確認対象であり、今回再現済みとはしない |
| [標準の対象者表示](js/rmmz_scenes.js#L1549-L1557) は表示時に対象ウィンドウのX座標を変更 | 生成直後の再配置だけでは足りない。表示・選択・閉じる遷移もAdapterで扱う |
| [タッチ操作](js/plugins/MobileTouchControls.js) は独自のDOM操作部、端末判定、`Input` 状態注入、キー割当を持つ | 全シーン共通の仮想コントローラーではなく、探索時だけの操作部とUI直接操作に分ける |
| [標準ボタン非表示](js/plugins/HideTouchBackMenuButtons.js) は複数シーンの戻る・メニュー・仲間切替ボタン生成を無効化 | 新UIの戻る／切替が完成する前に非表示だけを移植しない |
| [文字間隔補正](js/plugins/MainFontLetterSpacing.js) と登録設定に大きい負の字間がある | 文字を詰めて収めない。フォント計測・折返し・詳細表示を優先する |

共有中のゲームを読み取り確認した時点では、ブラウザーが **318×660 CSS px**、Canvas論理サイズが **816×1694**、UI領域が **808×616** だった。横方向の縮尺は約0.39倍で、標準26論理pxの文字なら表示上は約10 CSS px相当になる。これは縮尺からの概算であり、全画面・全フォントの実測値ではない。今回のブラウザー確認は探索画面のみ。

## 3. 見た目と情報設計

### デザイン方針

JRPGらしい「仲間・能力・道具・冒険の状況」が主役。濃紺の高不透明度パネル、落ち着いた金の見出し、明るい本文、細い区切り線を基本とする。背景の絵は残すが文字の背後は十分に暗くする。大きな装飾カードや常時アニメーションで一覧性を犠牲にしない。

- HP/MP/TPは色だけでなくラベルと数値を併記。選択は枠とマーカー、使用不可は理由も表示。
- 主操作は一か所。「使用」「装備」「購入」を曖昧な「OK」にしない。
- 名前は最大2行を許容。長文説明は折り返し＋縦スクロール。価格・所持数・消費MPを文字と重ねない。
- 顔画像は仲間の識別補助。狭い画面では小さくし、HP数値や状態を省略してまで大きく表示しない。
- UI文字サイズと演出軽減を設定可能にする。Canvas内UIのスクリーンリーダー対応は別課題であり、本案だけでアクセシビリティ対応完了とはしない。

### 表示サイズの初期目標（すべて表示上のCSS px）

| 項目 | PC | 縦型スマホ |
| --- | --- | --- |
| 本文 | 18、拡大可能 | 18、16未満へ自動縮小しない |
| 補助情報 | 14〜16 | 14〜16、重要数値は本文サイズ |
| 選択行 | 44以上 | 56以上、2行名なら自動拡張 |
| タッチ可能範囲 | タッチ利用時44×44以上 | 48×48以上、隣接間隔8以上を基本 |
| 余白 | 16〜24 | 12〜16＋セーフエリア |
| パネル | 一覧＋詳細の2〜3領域 | 主内容1領域＋操作欄、対象選択時だけモーダル |

高さ不足時は装飾・顔画像・常時説明を減らし、一覧と詳細をスクロールする。全体を縮小したり、確定ボタンを画面外へ追い出したりしない。初期最低検証幅は320、360以上を推奨とする。

## 4. 画面ごとの配置と操作

| 画面 | PC / 広い画面 | 縦型スマホ / 狭い画面 |
| --- | --- | --- |
| 探索 | 通常は仮想ボタンなし。メニューと状況ヒントを控えめに表示 | 下部に探索専用操作帯。移動と「調べる」を分離、メニューを明示。操作帯の背後にはイベント等の重要対象を置かない |
| メニュー | 左コマンド、中央に仲間、右または下に所持金・場所 | 上に場所と所持金、中央にスクロール可能な仲間一覧、下に2列のコマンド。設定等は「その他」へ |
| 道具 | 左に分類＋一覧、右に説明、使用時に対象者 | 上に分類、中央に一列一覧、下に選択中の要約＋「使用する」。対象は下部パネル |
| スキル | 使用者切替、スキル一覧、説明・消費MP、対象者 | 使用者を上部に固定。分類→スキル→対象の順。対象パネルにも使用者と消費MPを表示 |
| 装備 | 部位・候補・能力差分を並べる | 部位→候補→差分確認。対象仲間を固定表示し、「装備する」で確定 |
| ステータス | 基本能力と耐性等を並列表示 | 基本／能力／耐性のタブ。状態異常の名称と説明へタップでアクセス |
| ショップ | 商品一覧＋所持数／装備差分、数量を横に表示 | 購入／売却切替→商品→数量と合計金額。数量パネルを比較欄と同時に重ねない |
| 戦闘 | 上に短いログ、中央に戦場、下に仲間情報とコマンド | 上にログ、中央に戦場、下に仲間4人のコンパクトな2列表示＋入力パネル。スキル一覧・対象一覧は入力パネルを置換 |
| 会話・選択肢 | 読みやすい幅の会話欄＋選択肢 | 顔は縮小、本文幅優先。選択肢は48px以上でスクロール。メッセージを隠す配置は避ける |
| セーブ／ロード | スロット一覧と詳細 | 一列カード。日時・場所・仲間を識別可能に。上書き確認、オートセーブとの区別 |
| タイトル・設定 | 現在の操作機器に応じたガイド | ラベル付き大きい行。音量は＋／−でも変更可能。クレジットを残す |
| 名前入力・数値入力・イベント道具選択 | 標準の入力機能を維持 | タッチだけで完結。文字盤・桁選択・決定・戻るの到達性を個別検証 |

### 道具の状態遷移

`一覧を選択 → 説明を読む → 使用する → 対象者を選ぶ → この仲間に使う → 結果表示`

- PCもスマホも一覧クリック／タップは選択・説明表示。単発のタップで消費しない。
- キーボード／ゲームパッドは標準の方向操作と決定で進める。高速操作時に毎回マウス操作を要求しない。
- 戻るは「対象パネル→元の一覧→メニュー→探索」の順。選択位置、分類、スクロール位置を復元する。
- 回復後も対象パネルを保持し、連続使用を可能にする。所持数ゼロで使用不可にして理由を示す。
- 全体対象は「仲間全員に使う」と表示し、不要な一人選択を省く。対象なし／コモンイベント付き道具はMZ本来の使用処理へ渡す。
- 一覧をドラッグしてスクロールした指離しを決定扱いにしない。長押し専用の必須操作やホバー限定説明を作らない。

### 戦闘で特に守ること

1. 操作中の仲間の名前・HP/MP/TPと「何を選択中か」を固定表示する。
2. スキル選択中は説明とコスト、対象選択中は対象名を優先。不要なパネルは閉じる。
3. 小さい敵スプライトを正確にタップしなくても対象一覧から選べる。同名敵はA/B等で区別し、戦場側にも対応表示。
4. 戻るは対象→スキル一覧→コマンドへ。勝手に攻撃を確定しない。
5. 現在の [システム設定](data/System.json) はサイドビュー・TPBウェイト（`battleSystem: 2`）。UIだけでターン制へ変えない。
6. 独自パネルも [TPBの入力待機判定](js/rmmz_scenes.js#L3095-L3115) に参加させる。見た目が開いているだけで時間が進む状態を防ぐ。アクティブTPBは別途検証し、未検証のまま対応を宣言しない。
7. 確定直前に入力中アクター、アクション、対象の生存・使用可否を再検証。入力が無効になったら安全な状態へ戻す。[既存の攻撃時ガード](js/plugins/Keke_SpeedStarBattle.js#L1861-L1869) を上書きで失わない。
8. 演出中は操作欄を畳めるが、HP・状態の把握とメッセージを失わせない。勝利・敗北・逃走・報酬も対象範囲とする。

## 5. レスポンシブの技術設計

### 端末判定ではなく「使える幅」と「入力機器」

`LayoutProfile` と `InputProfile` を独立させる。縦長PCには狭幅レイアウト＋キーボード操作、横長タブレットには広幅レイアウト＋大きいタッチ範囲を適用する。ユーザーエージェントだけで「スマホ」を決めない。

- セーフエリア差引後の有効幅を基準に、初期値は720 CSS px未満が `compact`、720以上が `wide`。境界は実測後に調整する。
- 文字拡大やパネル最小幅により2列が入らなければ `compact` へ。高さ不足は別の制約として扱う。
- `auto / compact / wide` の設定と開発用プレビューを用意する。ただし `wide` 指定でも可読最小幅を破らない。
- `visualViewport`、CanvasのDOM矩形、セーフエリアを `ViewportService` だけが読み取る。未対応環境では `innerWidth/innerHeight` にフォールバック。

### 座標の所有者を一つにする

`ViewportService` はCSS表示矩形、Canvas論理矩形、UIセーフ矩形、世界表示矩形を返す。UIの18px、48pxは表示上の大きさであり、816幅を前提にした論理px固定値ではない。

- 変換例: `uiLogicalWidth = cssWidth × Graphics.width / canvasRect.width`。入力座標も同じ変換の逆写像を使用する。Canvasの位置、倍率、UIルートのオフセットを含める。
- 初期実装はMZのCanvas／Windowを継続利用。画面の論理サイズと `Graphics.boxWidth/boxHeight` は共通Viewport層だけが設定し、WindowLayerの原点補正もここで管理する。
- マップ拡大・カメラ、戦闘背景・バトラー、イベントピクチャは `WorldViewportAdapter` の責務。UI文字を拡大するために世界全体を拡大しない。
- MVPでは世界の座標系と既存ピクチャの816×624基準を維持する互換表示を優先。縦いっぱいの世界表示は別の検証項目とする。
- 互換表示時の余白／レターボックスを許容し、欠けるより優先する。縦拡張する場合はタイル描画範囲、マップ端、画面スクロール、タッチ移動逆変換、バトラー配置、アニメーション中心、ピクチャ原点・拡大を個別検証する。
- `devicePixelRatio` は描画解像度の問題として別扱い。タッチサイズ算定に二重適用しない。高DPIでのGPU負荷は実機測定で上限を決める。

### リサイズは状態を保って再配置

回転・ウィンドウ変更・ブラウザー操作バーの伸縮をまとめて次フレームに反映する。起動時だけの配置判定にしない。

1. 現在の選択ID、使用者ID、対象ID、スクロール、モーダル、フォーカスを退避。
2. 押下中の仮想入力と古いポインター操作をキャンセルし、誤確定を防ぐ。
3. 純粋関数 `LayoutResolver.resolve(scene, profile, metrics, state)` で矩形と表示状態を計算。
4. 必要なウィンドウだけ `move()`。サイズ変更時は `createContents()` と再描画、カーソル・子スプライト等も更新。毎フレーム作り直さない。
5. 選択IDの存在と使用可否を再検証して復元。消失時は有効な項目または一覧へ戻る。

## 6. 保守しやすい構成

**ソースは分割、配布は原則一つの生成済みプラグイン。** 大量の相互依存プラグインをユーザーに並べ替えさせない。ビルド導入は実装段階に行う（今回の提案では追加していない）。

| モジュール案 | 所有する責務 | 禁止すること |
| --- | --- | --- |
| `ViewportService` / `WorldViewportAdapter` | 表示サイズ、座標変換、世界表示の互換処理 | 個別シーン内でブラウザー寸法を独自取得 |
| `LayoutResolver` / `ThemeTokens` | 矩形、列数、余白、文字、配色 | ゲームデータ更新、`Input` 操作 |
| `InputRouter` / `FocusManager` | キー・パッド・ポインターの共通アクション、フォーカス | 表示幅によるキー割当変更、全シーンへの仮想OK注入 |
| `UIState` / `ViewModel` | 選択ID、説明、コスト、能力差分、画面状態 | セーブデータ構造へのUI都合の変更 |
| `SceneAdapter` | MZのシーン・ウィンドウと共通状態の接続 | 別シーンや`Window_Base`全体への無制限な書換え |
| `Widgets` | 一覧、仲間行、説明、数量、確認、操作ガイド | 各Widgetで独自のタッチ処理や画面判定 |
| `CompatibilityAdapters` | 速度変更、移動速度設定、クレジット等の連携 | ロード順だけに依存した不明な上書き |
| `Diagnostics` | 領域・当たり判定・フォーカス・入力元の可視化 | 本番での常時ログや毎フレーム全文字描画 |

既存Windowを可能な範囲でサブクラス化して使い、必要なシーンの生成・表示遷移にだけフックを置く。MZ本体は編集しない。フック一覧と対応MZバージョン（現状1.10.0）を管理する。

### 入力・拡張の契約

- `select / confirm / cancel / pagePrev / pageNext / menu` を意味上のアクションとして扱う。入力方式は最後に使った機器でガイドだけ切り替える。
- モーダル表示中に入力を受け取れるのは最上位の操作領域だけ。背景クリック、マップ移動、背後のウィンドウの決定を遮断する。
- 探索用タッチ操作だけはDOMを使う選択肢を残すが、ヒット領域を一元登録し、PointerとMZのTouch/Mouseへの二重配送を防ぐ。シーン終了、`blur`、`visibilitychange`、`pointercancel`で解除する。
- マウス・ゲームパッド由来の疑似クリックによるマップ移動抑止を保持する。タッチ移動は設定で許可する。移動スティックを離しただけで「調べる」を発火させない。
- 外部拡張は `registerMenuCommand({ id, label, enabled, handler })` 等の登録口を経由。命令の順序、条件付き非表示、長いラベルを検証し、固定の「4項目／6項目」を前提にしない。
- UI設定は `ConfigManager` に名前空間付きで保存し、旧設定には既定値を補う。UIの一時状態をゲームセーブへ混入させない。
- 色・余白・文字・タッチ範囲は共通トークンで調整。シーン別の座標補正パラメーターを大量に公開しない。

## 7. 既存プラグインの扱い

| 現行プラグイン | 最終的な方針 | 切替条件 |
| --- | --- | --- |
| `VerticalDisplayFullscreen` | Viewport層へ置換 | 世界表示・ピクチャ互換検証後。同時に解像度を所有しない |
| `FlexibleTopDownUI` | 置換 | 対応シーンを新SceneAdapterへ移行。新UIに重ねて有効化しない |
| `MobileTouchControls` | InputRouter＋探索操作部へ置換 | キー・パッド・タッチ、複数指、押下解除の回帰試験後 |
| `HideTouchBackMenuButtons` | 撤去 | 全移行画面に戻る／仲間切替を提供後。未移行画面は標準ボタンを復活させる |
| `MainFontLetterSpacing` | 新UIの通常字間で比較し、原則置換 | フォントと和文表示、会話・制御文字を検証。残す場合は対象範囲と計測方式を揃える |
| `DisableMouseMapClickMove` | 目的を保持してInputRouterへ統合 | 現行を有効のまま二重処理しない。Joy-Con等の疑似クリックも回帰試験 |
| `Keke_SpeedStarBattle` | 維持、専用互換Adapter | TPB・高速化・ログ・攻撃ガードの確認。速度／行動進行を新UIで再実装しない |
| `PlayerMoveSpeedOptions` | 維持 | 新設定画面に既存項目を引き継ぐ |
| `LicenseNotice` | 維持 | タイトル・設定からクレジットに到達可能にする |

開発中の試行は複製したプロジェクトまたは検証ブランチで実施する。旧UI群と新UI群は別プロファイルとし、本番登録は勝手に切り替えない。重複検出時は警告し、そのシーンの新Adapterを起動しない。部分移行は標準MZ画面をフォールバックとして使うが、標準画面までスマホ最適化済みとは扱わない。

## 8. 開発順序と合格条件

| 段階 | 作るもの | 次へ進む条件 |
| --- | --- | --- |
| 0: 合意 | 本提案＋独立した道具画面見本 | PCと縦型スマホの配置・使用フローを比較し方向性を決める |

初回MVPでクエスト管理・ミニマップ・クラフト等の新ゲーム機能は追加しない。UI基盤の安定が先。

### テスト行列

- サイズ: 320×568、360×640、390×844、430×932、816×624（現行PC）、1280×720、1920×1080。横向き844×390、720付近の境界、文字拡大125%・150%も検証。
- 環境: macOS NW.js、デスクトップブラウザー、iPhone Safari、Android Chrome。セーフエリア・アドレスバー伸縮・高DPIは実機で確認する。
- 入力: キーボードのみ、マウスのみ、ゲームパッドのみ、タッチのみ、タッチからキーボードへの切替。押下中の背景化・回転、複数指、ドラッグ後の指離し。
- データ: 空一覧、所持数0/1/最大、長い和文名、長い説明、1人/4人/控えあり、戦闘不能、使用不可、全体対象、複数スキル分類、装備不可、所持金不足。
- 会話: `\\V`、`\\N`、`\\C`、`\\I` 等の制御文字、顔表示、長文、選択肢、数値入力、イベント道具選択、会話中の回転。再配置でイベント命令を二重実行しない。
- 戦闘: 対象消失、入力者の戦闘不能、逃走不可、先制／不意打ち、全体技、コモンイベント、勝利・敗北、速度変更、ターン制は追加互換試験として区別。
- セーブ: 既存データ読込、手動上書き、オートセーブ、タイトル復帰後の再開。画面切替でUI一時状態やリスナーを残さない。

### 自動検証と定性的評価

`LayoutResolver` は純粋関数として、領域がセーフ矩形内・意図しない交差なし・最小サイズ確保をテストする。状態遷移は戻り先、無効対象、二重確定、選択復元をテストする。MZ統合ではビットマップ再生成と可視／active状態、入力到達先、イベント互換を確認する。

**リリース判定:** 重要文字の欠けなし、タッチ範囲48px以上、タッチだけで戻れる、同じ入力で二重使用しない、回転で選択を失わない、既存セーブ読込成功、既存速度・移動・クレジット機能維持。

性能は代表Android実機とPCで計測し、60fpsを目標にフレーム時間とメモリを比較する。全UIの毎フレーム再描画やDOMレイアウト取得を禁止し、変更時更新を基本にする。未測定段階で性能保証しない。

最後に「道具で回復」「装備を比較」「戦闘でスキル選択」を現行と新UIで同じ条件で試し、所要時間、誤操作、戻り操作の迷い、読みにくさを記録する。見本がきれいなだけでは採用しない。
